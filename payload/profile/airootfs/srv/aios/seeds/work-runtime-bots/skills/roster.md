# Roster

A roster is a list of jobs. It is not a cast of characters.

## Trigger

Creating, updating, or addressing standing work-runtime jobs that outlive a
single wake: “keep the build guests healthy,” “rotate logs on the fileserver
VM,” “run the nightly reconstruct-from-cold.”

## Do

- Address a job by path, slice, and skill. `jobs/build-guests.md` is a file.
- Record standing orders as envelope-adjacent operational constraints, with
  oracles the checker can run.
- Hand off with operational payload: last evidence, paths, the next oracle.

## Don’t

- Don’t name jobs as people. Don’t store a personality, a voice, or a
  memory-of-self per entry.
- Don’t let a roster entry hold host privilege “because it has been around
  a long time.”
- Don’t wake the OS agent as if it were a teammate on the roster.
